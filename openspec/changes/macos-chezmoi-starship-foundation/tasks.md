## Execution contract

- Work in the dependency order below; each work unit has a bounded start, finish, verification, and rollback boundary.
- Strict TDD is active. For every executable behavior, write and run the named failing check first (RED), implement only enough behavior to pass (GREEN), add independent or adversarial coverage where useful (TRIANGULATE), then simplify without changing behavior (REFACTOR).
- The repository has no configured test runner, linter, formatter, or type checker. The implementation must establish a small Bash-based isolated-HOME harness at `scripts/tests/macos-starship-test.sh`; the focused commands below are the authoritative checks until a project runner is introduced.
- Tests, fixtures, shims, and user-facing documentation for a behavior stay in the same work unit as that behavior.
- Automated tests must never use the developer's real home, default chezmoi state, a real Ghostty installation, macOS or Apple Terminal preferences, network, or local backups. Use disposable directories below a test-created fixture root and clean them with a trap.
- Ghostty installation is an external prerequisite for manual verification only. No implementation task may install, uninstall, launch, or otherwise manage Ghostty; preview/apply may manage `~/.config/ghostty/config` even when Ghostty is absent.
- Use only generic fixture values and `$HOME`-relative output. Never log shell contents, backup locations, absolute home paths, credentials, or private host data.
